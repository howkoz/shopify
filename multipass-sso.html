Multipass SSO Integration

Single sign-on for seamless customer authentication between Unicity platforms and Shopify stores.

What Is Multipass

Multipass is a Shopify Plus-exclusive Single Sign-On (SSO) mechanism that allows external authentication systems to create and log in customers to Shopify without requiring separate account registration. It uses AES-256-CBC encrypted tokens passed via URL parameters, enabling seamless authentication. Customer accounts are automatically created on first login, with all attributes populated from the external system.

Why Unicity Needs Multipass

  • Existing Distributor Accounts: Distributors already have Unity accounts with ID, rank, and commission data
  • Avoid Duplicate Registrations: Customers may have existing Unicity accounts; eliminate forced separate Shopify registration
  • Attribute Passing: Pass distributor attributes (Unity ID, rank, region) directly into Shopify customer records
  • Single Login: Enable login across Unicity.com and Shopify stores using the same credentials
  • B2B Support: B2B customers can log in with existing credentials, improving onboarding
  • Unified Identity: Maintain a single source of truth for customer data across platforms

How Multipass Works

The Multipass authentication flow involves five key steps:

1
User Logs Into Unicity Portal

Customer authenticates with existing Unicity credentials on Unicity.com or internal portal

↓
2
Unicity Server Generates Multipass Token

Backend creates encrypted JSON token containing email, name, ID, rank, and other attributes using AES-256-CBC

↓
3
User Redirected to Shopify

User's browser is redirected to: https://store.myshopify.com/account/login/multipass/{token}

↓
4
Shopify Decrypts & Creates Customer

Shopify validates the signature, decrypts token, creates or matches customer, and sets session

↓
5
User Lands on Shopify Store

Customer is fully authenticated and redirected to specified return URL (e.g., wholesale collections)

Token Structure

The Multipass token is an encrypted JSON payload containing customer data. Before encryption, the JSON structure looks like this:

JSON Payload Structure
{
  "email": "distributor@unicity.com",
  "created_at": "2026-03-30T14:30:00Z",
  "first_name": "John",
  "last_name": "Distributor",
  "tag_string": "distributor,gold-rank,usa,wholesale",
  "identifier": "UNITY-12345",
  "remote_ip": "203.0.113.45",
  "return_to": "/collections/wholesale",
  "addresses": [
    {
      "address1": "123 Business Ave",
      "city": "Salt Lake City",
      "province": "UT",
      "zip": "84101",
      "country": "United States"
    }
  ]
}

Required Fields

  • email – Customer email address (used for matching existing customers)
  • created_at – ISO 8601 timestamp when token was generated (must be recent; expires in 15 minutes)

Optional but Recommended Fields

  • first_name, last_name – Customer name
  • tag_string – Comma-separated tags for segmentation (e.g., "distributor,gold-rank,usa")
  • identifier – Unique external ID (e.g., Unity ID) for tracking
  • remote_ip – Customer's IP address for security validation
  • return_to – URL to redirect after successful login
  • addresses – Array of shipping addresses to auto-populate

Implementation Steps

  1. Enable Multipass in Shopify Admin – Navigate to Settings → Customer accounts → Enable Multipass
  2. Copy the Multipass Secret Key – Store securely in environment variables (never commit to version control)
  3. Implement Token Generation – Add token generation logic to your Unicity backend
  4. Create Login Endpoint – Build an endpoint that generates tokens and redirects to Shopify
  5. Test with Sample Customer – Verify token generation, decryption, and customer creation
  6. Map Unity Fields to Shopify – Ensure all customer attributes flow correctly

Code Examples

Python Token Generation

Python (with cryptography library)
import json, hashlib, hmac, base64, os
from datetime import datetime
from cryptography.hazmat.primitives.ciphers import Cipher, algorithms, modes
from cryptography.hazmat.backends import default_backend

def generate_multipass_token(secret, customer_data):
    # Step 1: Derive encryption and signing keys from secret
    key_material = hashlib.sha256(secret.encode()).digest()
    encryption_key = key_material[:16]
    signing_key = key_material[16:32]

    # Step 2: Add created_at timestamp
    customer_data['created_at'] = datetime.utcnow().isoformat() + 'Z'

    # Step 3: Convert to JSON and pad with PKCS7
    json_data = json.dumps(customer_data).encode()
    block_size = 16
    padding_length = block_size - (len(json_data) % block_size)
    padded_data = json_data + bytes([padding_length] * padding_length)

    # Step 4: Encrypt with AES-256-CBC
    iv = os.urandom(16)
    cipher = Cipher(algorithms.AES(encryption_key), modes.CBC(iv), backend=default_backend())
    encryptor = cipher.encryptor()
    encrypted = iv + encryptor.update(padded_data) + encryptor.finalize()

    # Step 5: Sign with HMAC-SHA256
    signature = hmac.new(signing_key, encrypted, hashlib.sha256).digest()

    # Step 6: Return base64 URL-safe token
    token_data = encrypted + signature
    token = base64.urlsafe_b64encode(token_data).decode().rstrip('=')

    return token

# Usage
secret = os.environ.get('SHOPIFY_MULTIPASS_SECRET')
customer = {
    'email': 'john@example.com',
    'first_name': 'John',
    'last_name': 'Distributor',
    'identifier': 'UNITY-12345',
    'tag_string': 'distributor,gold-rank,usa',
    'return_to': '/collections/wholesale'
}
token = generate_multipass_token(secret, customer)
redirect_url = f'https://store.myshopify.com/account/login/multipass/{token}'

Node.js Token Generation

Node.js (with crypto module)
const crypto = require('crypto');

function generateMultipassToken(secret, customerData) {
    // Step 1: Derive keys from secret
    const keyMaterial = crypto.createHash('sha256').update(secret).digest();
    const encryptionKey = keyMaterial.slice(0, 16);
    const signingKey = keyMaterial.slice(16, 32);

    // Step 2: Add timestamp
    customerData.created_at = new Date().toISOString();

    // Step 3: Convert to JSON and pad
    const jsonData = Buffer.from(JSON.stringify(customerData));
    const blockSize = 16;
    const paddingLength = blockSize - (jsonData.length % blockSize);
    const paddedData = Buffer.concat([
        jsonData,
        Buffer.alloc(paddingLength, paddingLength)
    ]);

    // Step 4: Encrypt with AES-256-CBC
    const iv = crypto.randomBytes(16);
    const cipher = crypto.createCipheriv('aes-256-cbc', encryptionKey, iv);
    const encrypted = Buffer.concat([iv, cipher.update(paddedData), cipher.final()]);

    // Step 5: Sign with HMAC-SHA256
    const signature = crypto.createHmac('sha256', signingKey).update(encrypted).digest();

    // Step 6: Return base64 URL-safe token
    const token = Buffer.concat([encrypted, signature])
        .toString('base64')
        .replace(/\+/g, '-')
        .replace(/\//g, '_')
        .replace(/=/g, '');

    return token;
}

// Usage
const secret = process.env.SHOPIFY_MULTIPASS_SECRET;
const customer = {
    email: 'john@example.com',
    first_name: 'John',
    last_name: 'Distributor',
    identifier: 'UNITY-12345',
    tag_string: 'distributor,gold-rank,usa',
    return_to: '/collections/wholesale'
};
const token = generateMultipassToken(secret, customer);
const redirectUrl = `https://store.myshopify.com/account/login/multipass/${token}`;

Security Considerations

Critical: Secret Key Management Never commit your Multipass secret key to version control. Store it as an environment variable on your server only. Never expose it to client-side code.
  • Server-Side Storage Only: Multipass secret must never be exposed to client-side JavaScript or committed to repositories
  • Token Expiration: Tokens expire 15 minutes after creation (verified by created_at timestamp). Reject any stale tokens
  • HTTPS Only: All redirect URLs must use HTTPS; never pass tokens over unencrypted HTTP
  • Periodic Key Rotation: Rotate your Multipass secret key every 90 days. This will invalidate all existing tokens, so plan accordingly
  • Audit Logging: Log all Multipass login attempts with timestamp, email, and IP address for security audits
  • IP Validation: Compare the remote_ip in the token with the request IP to prevent token theft
  • Rate Limiting: Implement rate limiting on your token generation endpoint to prevent brute-force attacks
  • Signature Verification: Always verify the HMAC-SHA256 signature before decrypting; corrupted or tampered tokens will fail validation
Token Theft Prevention If a token is intercepted, an attacker could potentially log in as that customer. Always use HTTPS, validate remote IP, and keep tokens short-lived.

Integration Architecture for Multi-Store

Unicity plans to expand Shopify to multiple regional stores. Here's how Multipass integrates across the expansion:

Key Principles

  • One Secret Per Store: Each expansion store (US, EU, Japan) has its own Multipass secret key
  • Region-Based Routing: The Unity login system determines which store to redirect to based on distributor region
  • Unified Identity: All customers are identified by email; the same customer can access multiple stores with one login
  • Store-Specific Tags: Use tags to track which stores a customer has accessed or has permissions for

Region-to-Store Mapping

function getStoreForDistributor(distributorData) {
    const region = distributorData.region.toLowerCase();
    return storeMapping[region] || storeMapping['usa'];
}

Cross-Store Customer Matching

Since all customers are matched by email, a distributor logging into the EU store with the same email address will be recognized and logged in automatically. The Multipass token includes region-specific attributes (currency, language, locale), but the customer record is unified. Use tags like "store:us", "store:eu", "store:japan" to track which stores a customer has accessed.

Benefit: Seamless Cross-Store Experience A US distributor who travels to Europe can log into the EU store with their same email and immediately see their account, history, and preferences—all without re-registration.
