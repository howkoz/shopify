Scripts to Functions Migration

DEADLINE: June 30, 2026. Shopify Scripts (Ruby) are being replaced by Shopify Functions (Rust/JS). Migration plan for Unicity International.

CRITICAL: Shopify Scripts retire June 30, 2026. All custom checkout, shipping, and payment scripts must be migrated to Shopify Functions before this date or they will stop working.

What's Changing

Shopify is sunsetting its legacy Scripts platform and replacing it with Shopify Functions. This is a fundamental shift in how customizations are built and deployed.

Shopify Scripts (Legacy - Retiring)

  • Language: Ruby-based
  • Platform: Runs in Script Editor app (Plus-exclusive)
  • Capabilities: Line item discounts, shipping customization, payment customization
  • End of Life: June 30, 2026

Shopify Functions (New - Required)

  • Language: Wasm-based (Rust, JavaScript, or any Wasm language)
  • Platform: Runs as app extensions
  • Capabilities: Order routing, fulfillment constraints, cart transforms, bundles, plus all legacy Script use cases
  • Advantages: Faster execution (Wasm), more capabilities, better developer experience

Key Differences

Aspect Shopify Scripts Shopify Functions
Language Ruby Rust, JavaScript, or any Wasm language
Execution Interpreted WebAssembly (Wasm) - faster, more secure
Deployment Script Editor app App extension (Shopify CLI)
Plan Requirement Shopify Plus only All plans (using custom app)
Capabilities 3 use cases 6+ use cases, more extensibility
Performance Good Excellent (compiled, sandboxed)

Script Types and Function Equivalents

Script Type What It Does Function API Replacement
Line Item Scripts Apply discounts on cart items (BOGO, tiered pricing, bundle discounts, loyalty rewards) Discount Function API (product discounts, order discounts, shipping discounts)
Shipping Scripts Modify shipping rates (hide/rename/reorder rates, free shipping rules, weight-based rates) Delivery Customization Function API (delivery options customization)
Payment Scripts Modify payment methods (hide/reorder/rename gateways based on conditions, conditional payment methods) Payment Customization Function API (payment method display rules)

Step-by-Step Instructions

Step 1: Install Shopify CLI

Terminal
npm install -g @shopify/cli

Step 2: Create Function Extension

Choose the template based on your use case:

Terminal - Discount Function
shopify app generate extension --template discount_function
Terminal - Delivery Customization Function
shopify app generate extension --template delivery_customization_function
Terminal - Payment Customization Function
shopify app generate extension --template payment_customization_function

Step 3: Write Logic in JavaScript

Example: BOGO discount (Line Item Script replacement)

JavaScript - Discount Function
export function discount(input) { const cartItems = input.cart.lines; // Find items matching product ID const matchingItems = cartItems.filter( item => item.merchandise.product.id === 'gid://shopify/Product/12345' ); if (matchingItems.length >= 2) { // Apply 50% off to second matching item const secondItem = matchingItems[1]; return { discounts: [ { targets: [ { lineItem: { id: secondItem.id } } ], value: { percentage: 0.5 } } ] }; } return { discounts: [] }; }

Step 4: Test Locally

Terminal
shopify app function run --input-file test-input.json

Step 5 & 6: Deploy and Configure

Terminal
shopify app deploy

Common Migration Patterns

See how common Script patterns translate to Functions:

Pattern 1: BOGO Discount (Buy One Get One)

Before: Ruby Script

Input.cart.line_items.each do |item| if item.variant.product.title.include?('Special') item.discount = item.price * 0.5 end end

Location: Script Editor

Trigger: Automatic on cart update

After: JavaScript Function

export function discount(input) { const discounts = []; input.cart.lines.forEach(line => { if (line.merchandise.product .title.includes('Special')) { discounts.push({ targets: [{ lineItem: { id: line.id } }], value: { percentage: 0.5 } }); } }); return { discounts }; }

Location: App extension

Deployment: Shopify CLI

Pattern 2: Free Shipping Over $100

Before: Shipping Script

Input.cart.shipping_rates.each do |rate| if Input.cart.subtotal_price >= 10000 rate.price = 0 end end

Logic: Modify shipping rates

After: Delivery Customization

export function deliveryCustomization(input) { const subtotal = input.cart.subtotalAmount .amount; return input.deliveryOptions.map(option => { if (subtotal >= 100) { return { ...option, cost: { amount: "0.00" } }; } return option; }); }

Logic: Hide/modify delivery options

Pattern 3: Hide PayPal for Subscriptions

Before: Payment Script

Input.payment_methods.each do |method| if Input.cart.line_items.any? { |item| item.subscription? } method.hide if method.name.include?('PayPal') end end

Use: Payment method visibility

After: Payment Customization

export function paymentCustomization(input) { const hasSubscription = input.cart.lines .some(line => line.isSubscription); if (hasSubscription) { return input.paymentMethods .filter(method => !method.name.includes('PayPal') ); } return input.paymentMethods; }

Use: Payment method filtering

Testing Strategy

Comprehensive testing is essential for a smooth migration. Follow this strategy:

Pre-Deployment Testing

  • Unit Tests: Test Function logic locally with sample inputs before deployment
  • Edge Cases: Test with empty cart, single item, high-value orders, international scenarios
  • Integration: Test Functions with real product and order data

Development Store Testing

  • Deploy to Dev Store First: Never deploy directly to production
  • Test Full Checkout Flow: Go through complete checkout process with Functions enabled
  • Verify Outputs: Confirm discounts, shipping rates, or payment methods match expectations

Parallel Run (A/B Testing)

  • Keep Scripts Active: Continue running existing Scripts on main checkout
  • Deploy Functions to Test Checkout: Use test checkout flow with new Functions
  • Compare Results: Run sample transactions and compare discount amounts, rates, and options
  • Monitor Metrics: Track checkout abandonment, completion rate, error rates

Cutover Testing

  • Gradual Traffic Shift: Start with 5% traffic on Functions, increase incrementally
  • Real-Time Monitoring: Watch for errors, unexpected behavior, customer complaints
  • Rollback Plan: Keep Scripts active as fallback for 2 weeks during cutover
  • Customer Validation: Ask internal test customers to verify experience

Validation Checklist

  • Discount amounts match Script calculations (within 1% tolerance)
  • Shipping rates display correctly for all regions
  • Payment methods show/hide based on cart conditions
  • No errors in checkout flow or error logs
  • Checkout completion rate is maintained or improved
  • Customer support receives no new complaints about pricing/shipping/payments

Risk Assessment

Different script types carry different risks. Understand and mitigate each:

High Risk: Payment Scripts

HIGH RISK

Why: Wrong payment options = lost sales, compliance issues, customer confusion

Examples: Hiding PayPal incorrectly, showing forbidden payment methods, conditional payment gateways

Mitigation: Extensive testing with all payment scenarios, A/B test thoroughly, have immediate rollback plan

Medium Risk: Shipping Scripts

MEDIUM RISK

Why: Wrong shipping rates = margin erosion, customer complaints, lost revenue

Examples: Free shipping rules, weight-based rates, carrier rate modifications, international shipping

Mitigation: Test with diverse cart scenarios (light/heavy, domestic/international), monitor margin impact

Lower Risk: Line Item Scripts

LOWER RISK

Why: Wrong discounts = fixable with manual adjustments, limited immediate impact

Examples: BOGO discounts, tiered pricing, bundle discounts, loyalty rewards

Mitigation: Test common scenarios, verify calculations, monitor discount redemption

Overall Risk Mitigation Strategy

  1. Prioritize by Risk: Migrate payment scripts first (highest risk = most attention needed)
  2. Test Extensively: Every Function must pass unit, integration, and A/B tests
  3. Phased Deployment: Don't deploy all Functions at once; roll out in phases
  4. Have Rollback Plan: Keep Scripts active for 2 weeks during cutover for safety
  5. Monitor Everything: Set up alerts for error rates, conversion rates, and margin changes
  6. Communication: Notify customer success, support, and finance teams of migration timeline
