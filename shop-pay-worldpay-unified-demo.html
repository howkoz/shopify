Shop Component Architecture

SHOP COMPONENT

Separation of Responsibilities

Shop Component allows non-Shopify storefronts to offer Shop Pay. Unicity remains source of truth for products, pricing, taxes, and shipping. Shopify only handles payment UI and processing.

flowchart LR subgraph UNICITY["🟢 UNICITY HANDLES"] U1[Product Catalog] U2[Cart Management] U3[Tax Calculation] U4[Shipping Rates] U5[Inventory] U6[Order Management] end subgraph SHOPIFY["🟣 SHOPIFY HANDLES"] S1[Shop Pay Modal] S2[Customer Auth] S3[Saved Wallets] S4[Payment Processing] end U1 --> S1 S3 --> U4 U4 --> S1 S1 --> S4 S4 --> U6
SHOP PAY PATH

Shop Component Event Flow

Event-driven architecture. Shopify popup emits events, Unicity backend responds with updated PaymentRequest within 15 seconds.

flowchart LR C[Customer] --> SP[Shop Pay Popup] SP -->|"shippingaddresschange"| FE[Unicity Frontend] FE -->|"Calculate rates"| BE[Unicity Backend] BE -->|"Return rates"| FE FE -->|"complete()"| SP SP -->|"Pay Now"| PAY[Shopify Payments] PAY -->|"Webhook"| BE
WORLDPAY PATH

Native Checkout Flow

Traditional checkout. Unicity owns entire flow. Worldpay tokenizes card, token stored in Unicity vault for subscription billing.

flowchart LR C[Customer] --> A[Address Form] A --> S[Shipping Selection] S --> WP[Worldpay Tokenize] WP --> R[Review] R --> PAY[Worldpay Process] PAY --> V[Vault Token] V --> O[Order Complete]
⚠️ LIMITATION

Subscription Support

Shop Component does NOT currently support subscriptions. For subscription products, customers must use the Worldpay path where Unicity owns the token for recurring billing.

ScenarioRecommended PathReason
One-time purchaseShop Pay ✓Higher conversion, wallet auto-fill
First subscription orderWorldpay ⚠Need token for recurring billing
Recurring subscriptionWorldpay ✓Batch system charges vaulted token
