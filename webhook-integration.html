This event-driven architecture enables real-time synchronization between Shopify and downstream systems. All webhook events flow through a centralized API Gateway middleware that:

  • Validates HMAC signatures for security
  • Routes events to appropriate target systems
  • Implements retry logic and dead-letter queues
  • Provides audit logging and monitoring
  • Handles rate limiting and throttling

Shopify Plus API Advantages

GraphQL Admin API

500 points/second rate limit (vs 50 for standard plans). Efficient query structure reduces overhead for complex data operations.

REST Admin API

20 requests/second rate limit (vs 2 for standard plans). Flexible bucket model with 40-request burst capacity.

Webhook Delivery

Guaranteed delivery with 19 automatic retries over 48 hours. Exponential backoff between retries ensures reliable event processing.

Mandatory Webhooks

Certain webhook topics are required for app compliance. Shopify enforces subscription to critical events for data consistency.

HMAC Verification

SHA-256 signature validation included in every webhook. X-Shopify-Hmac-SHA256 header authenticates event source.

API Versioning

Pin webhooks to specific API versions (e.g., 2024-01). Automatic migration support when upgrading versions.

Webhook Configuration

Configuration Steps

  1. Navigate to Shopify Admin → Settings → Notifications
  2. Scroll to Webhooks section
  3. Click Create webhook
  4. Select webhook topic (e.g., orders/create)
  5. Enter webhook endpoint URL (must be HTTPS)
  6. Select format: JSON (recommended) or XML
  7. Verify API version is pinned (e.g., 2024-01)
  8. Click Save webhook

Alternative: Configure via GraphQL API using the webhookSubscriptionCreate mutation.

GraphQL Webhook Subscription Mutation mutation CreateWebhook { webhookSubscriptionCreate( topic: ORDERS_CREATE webhookSubscription: { callbackUrl: "https://api.example.com/webhooks/orders" format: JSON } ) { userErrors { field message } webhookSubscription { id topic format callbackUrl createdAt } } }
Best Practice: Always pin API versions in webhook configurations. This ensures your webhook handler receives consistent schema versions even when Shopify updates the API. Example: API version 2024-01 remains stable regardless of current platform version.

Security & Verification

HMAC Verification

Every webhook includes the X-Shopify-Hmac-SHA256 header containing a SHA-256 HMAC signature. Verify this signature using your webhook endpoint's shared secret to confirm the request originated from Shopify.

Python Example:

Python - HMAC Verification import hmac import hashlib import base64 def verify_webhook(data, hmac_header, secret): # Compute HMAC-SHA256 of request body computed = base64.b64encode( hmac.new( secret.encode(), data, hashlib.sha256 ).digest() ).decode() # Compare with header (constant-time comparison) return hmac.compare_digest(computed, hmac_header) # Usage in Flask: @app.route('/webhooks/orders', methods=['POST']) def handle_webhook(): data = request.get_data() hmac_header = request.headers.get('X-Shopify-Hmac-SHA256') if not verify_webhook(data, hmac_header, WEBHOOK_SECRET): return 'Unauthorized', 401 # Process webhook... return '', 200

Node.js Example:

Node.js - HMAC Verification const crypto = require('crypto'); function verifyWebhook(data, hmacHeader, secret) { // Compute HMAC-SHA256 of request body const computed = crypto .createHmac('sha256', secret) .update(data, 'utf8') .digest('base64'); // Compare with header (constant-time comparison) return crypto.timingSafeEqual( Buffer.from(computed), Buffer.from(hmacHeader) ); } // Usage in Express: app.post('/webhooks/orders', (req, res) => { const hmacHeader = req.headers['x-shopify-hmac-sha256']; if (!verifyWebhook(req.rawBody, hmacHeader, WEBHOOK_SECRET)) { return res.status(401).send('Unauthorized'); } // Process webhook... res.status(200).send(''); });
Security Requirements:
  • HTTPS Only: All webhook endpoints must use HTTPS (TLS 1.2+)
  • Timeout: Respond with HTTP 200 within 5 seconds
  • Async Processing: Queue webhooks and process asynchronously to avoid timeout
  • Idempotency: Implement idempotent handlers (webhooks may retry)
  • HMAC Verification: Always verify X-Shopify-Hmac-SHA256 header

Error Handling & Retries

Shopify Retry Policy

When your webhook endpoint fails to respond with HTTP 200 within 5 seconds, Shopify automatically retries delivery:

  • 19 automatic retries over 48 hours
  • Exponential backoff between retry attempts (15 min, 30 min, 1 hour, etc.)
  • After 19 failures: Webhook marked as "removed" (requires manual re-registration)
Retry Attempt Time After Initial Failure Cumulative Duration
Attempt 1 (Initial) Immediate 0 minutes
Attempt 2 ~1 minute 1 minute
Attempt 3 ~2 minutes 3 minutes
Attempt 4 ~5 minutes 8 minutes
Attempt 5 ~15 minutes 23 minutes
Attempts 6-20 Increasing intervals Up to 48 hours

Monitoring & Dead-Letter Queues

  • Check Status: Admin → Settings → Notifications → view webhook delivery status
  • Event Logs: GraphQL API provides webhook event delivery history
  • Dead-Letter Queue: Implement separate queue for events that fail all retries
  • Alerts: Monitor failed webhook delivery and trigger alerts for manual intervention
  • Idempotency: Track processed event IDs to handle duplicate deliveries
Best Practice: Implement a message queue (Redis, RabbitMQ, AWS SQS) between your webhook endpoint and processing logic. Respond immediately with 200 to Shopify, then queue the event for asynchronous processing. This prevents timeout failures and ensures reliable event handling.

Rate Limits for Shopify Plus
API Type Shopify Plus Limit Standard Plan Limit Limiting Model
GraphQL API 500 points/second 50 points/second Query cost model (each field has point value)
REST API 20 requests/second 2 requests/second Token bucket (40-token burst)
Webhook Delivery No explicit limit Unlimited incoming webhooks
Bulk Operations 10 concurrent jobs Ideal for large data syncs (products, orders, customers)

Rate Limit Strategies

  • GraphQL Efficiency: Query exactly the fields you need to minimize point cost
  • Batch Operations: Use Bulk Query API for large data exports (free of rate limits)
  • Pagination: Use cursor pagination to avoid repeated large queries
  • Webhook Processing: No rate limits on receiving webhooks; process asynchronously
  • Token Bucket: For REST API, use exponential backoff when approaching limits
